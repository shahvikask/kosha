# Native GUDNAT01 typed archive v1 — implementation contract

**Status:** Test-backed internal primitive, NOT a production recovery/export acceptance or authorization to automatically back up.

**Format:** Binary `GUDNAT01` is distinct from legacy `GUDVLT01` and `KOSHA1`. Header: 8-byte ASCII magic; 4-byte big-endian PBKDF2-SHA256 rounds (600,000); 16-byte random salt; 12-byte random nonce. AES-256-GCM authenticates the 40-byte header as AAD and ciphertext with 128-bit tag. PBKDF2 input domain is `GrowUrDhan-Native-v1\n` + trimmed lowercase owner email + `\n` + **separate owner-chosen backup password**, distinct from Android account password. No password or source plaintext is persisted by this codec.

Authenticated payload `GV9SNAP1` + schema version 9 contains bounded schema object definitions (including triggers/indexes and opaque SQL metadata that is never executed), table/column descriptions, full typed v9 physical cells. SQLite storage classes NULL/INTEGER/TEXT/BLOB/REAL are distinct; integers use 64-bit big-endian, REAL uses exact IEEE-754 raw bits; text rejects malformed UTF-8. Total plaintext bound 64 MiB; internal row/object/cell limits are enforced before decode/allocation.

**Restore:** Only an isolated, new, empty SQLCipher v9 candidate with identical trusted physical schema is eligible; source object/column metadata and ALL cell values must match a re-read after SQL insert, with full foreign-key/SQLCipher integrity and rollback on mismatch. Unknown historical/extension metadata is retained in encrypted archive but a candidate lacking its schema must fail closed; it is **not** auto-executed or silently discarded.

**Required integration before UI/SAF:** owner/PAN/DOB/security-answer/Terms proof; durable single-use claim; independent Keystore candidate; locked no-overwrite key/database publication; crash/power loss and low-storage recovery; full real-device and old encrypted fixture proof; lifecycle-safe password clearance; separate user consent to destination/retention. No legacy downgrade or automatic SAF on-open/CAS triggers are permitted until accepted.

## Owner-bound native recovery bridge — October 21, 2026

New internal `NativeV9RecoveryProof` and `NativeV9NewDeviceRestore` integrate GCM-decrypted source account recovery against independent password/PAN/DOB/two answers, persisted Terms version, exact typed snapshot digest, secure Android device lock, immutable preview, durable single-use claim, Keystore-protected independent SQLCipher candidate, closed-file readback and no-overwrite key/DB publication. The encrypted stage is named `restore-pending.v1.kosha` (legacy name used only as a private quarantine; the GUDNAT01 header is verified strictly), and an interrupted claim is NEVER silently discarded. Source field loss or incompatible extension schema rejects publication. No plaintext disk copy. Recovery snapshots are wiped from process buffers on exit.

This source is not wired to the user-facing restore UI; none of the new tests demonstrates actual positive `publishAfterOwnerReview` on PIN-secured physical hardware. Outstanding owner-approved UI authorization, Terms-event storage, durable GUDNAT-specific read-only crash inspector, realistic ENOSPC/power-loss, cross-phone and Keystore invalidation tests remain mandatory. [Exact-source evidence #39595814842](https://github.com/shahvikask/kosha/actions/runs/39595814842) passed targeted tests only. Keep automatic SAF scheduling disabled.


## PIN-secured recovery and immutable Terms acceptance — October 21, 2026

`NativeV9RestoreConsentJournal` persists a current-new-device Terms event (version, text ID and ISO timestamp) in a CREATE_NEW+fsynced protected journal tied to the **canonical full typed financial snapshot SHA256**, after `RestoreOnceJournal.claimOnce` and before candidate key creation. Financial, source and historical Terms rows are kept losslessly unchanged. The new receipt is checked before publication and in independent `NativeV9RecoveryInspector`. That inspector authenticates staged GCM, owner recovery credentials, exact persistent claim and Terms evidence, examines candidate key/DB or live key/DB ambiguity and opens existing SQLCipher READ_ONLY to compare every source table and typed value. Its VERIFIED_* forensic states do not approve resumption, cleanup, repair or overwrite.

At [source `3f4fafd6`](https://github.com/shahvikask/kosha/commit/3f4fafd6f18e92144d27578d0644badaa3c83f13) [targeted CI #39599595528](https://github.com/shahvikask/kosha/actions/runs/39599595528), original [artifact #12345568296](https://github.com/shahvikask/kosha/actions/runs/39599595528/artifacts/12345568296), 10/10 PIN-secured API35 tests and 144/144 JVM tests passed with no skipped/failure cases. The positive test asserted Android `KeyguardManager.isDeviceSecure`, restored encrypted v9 into a different **sandbox context on the same emulator**, re-opened with wrapped Keystore key, verified >2^53 original integer money, and confirmed replay/no-overwrite. Tests cover claim-only, interrupted key/candidate, tampered Terms, and **synthetically** thrown ENOSPC; they do not prove a real full device, two independent physical Keystores/phones, genuine exhausted storage or post-power-loss resume. Keep external production Compose UI, auto SAF schedule, final AppSec and owner acceptance blocked until independently verified.

## Manual native candidate continuation contract — October 21, 2026

`NativeV9ManualResume` can accept only an already authenticated `VERIFIED_CANDIDATE` with an intact durable claim, source data, accepted current Terms, wrapped key and closed SQLCipher candidate. `prepare` is read-only; `publish` requires a second explicit owner approval and secure Android lock, and under a single exclusive lifecycle lock revalidates the entire staged GCM financial snapshot, immutable fingerprints, key/candidate names and SQLite physical cells. It permits only separate candidate key+database or a previously published key with unpublished candidate DB. `EncryptedRestorePublisher.publishReservedAtomic` is the same no-replace primitive for key and DB; never clear, overwrite, delete, repair, or retry automatically. Empty destination tombstones and ambiguous evidence remain BLOCKED, including after an interrupted manual resume.

The Compose route exposes separate forensic and manual-resume confirmations. The pending 19 Android instrumentation methods include distinct process launches separated by app force-stop but are **NOT YET VERIFIED** against new exact SHA `8b636827c84f229848f7c4ed2fa4e48f4721bc71`; original [#39605041139](https://github.com/shahvikask/kosha/actions/runs/39605041139) 12/12 is older code. Real power loss, actual disk exhaustion, another physical device, historical archive source fixtures, and complete UI picker/OS challenge flow remain blocked. SAF automatic scheduling remains off.
